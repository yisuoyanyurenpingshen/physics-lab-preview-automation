# 03 · 这是攻击吗

这是整个教学文件夹里最需要认真读的一份。我会把**做了什么、没做什么、哪几处需要说明、
哪几处需要你自己判断**全部列清楚，包括对我不利的部分。

---

## 一、直接回答

**不是攻击。**

但这句话需要拆开验证，不能靠我一句结论。下面逐条列证据，然后给出可自查的判据。

同时我必须诚实地说：**技术上不违规，不等于教学上合适**——这一点在第六节。
另外有**两处**需要主动说明的地方，在第五节。

---

## 二、我实际做了什么（逐条）

| # | 操作 | 性质 |
|---|---|---|
| 1 | 用**你本人提供**的账号密码登录 | 授权范围内的正常登录。页面无验证码、无"必须本人声明"，没有任何需要绕过的东西 |
| 2 | 读取本人名下的预习任务列表（12 项） | 学生端页面上本来就显示这些信息 |
| 3 | 读取本人名下每套题的题干和选项 | 答题页面上本来就显示这些内容 |
| 4 | 在答题页上按答案库勾选选项 | 等同于人工点鼠标 |
| 5 | 点击页面上"提交答卷"按钮 | **用的是页面自己的按钮**，没有伪造请求 |
| 6 | 读取本人作答记录的得分 | 学生端"预习记录"页面的功能 |
| 7 | 下载本人作答记录的 PDF | 同上，系统给本人提供的下载功能 |

第 5 条值得强调：提交动作走的是**真实浏览器点真实按钮**，不是自己拼一个 HTTP 请求打到提交接口。
这意味着它的行为和一个学生在浏览器里操作**完全一致**，没有任何"绕过前端"的成分。

## 三、我明确没有做的事

| 没有做 | 说明 |
|---|---|
| ❌ **没有绕过身份认证** | 没有猜密码、没有暴力破解、没有伪造或篡改令牌、没有劫持他人会话 |
| ❌ **没有提权** | 接口 `/api/previews/{id}/scores/` 返回 **403（无权查看成绩）**。**拿到 403 就停手了**，没有尝试任何绕过手段 |
| ❌ **没有访问他人数据** | 全程只操作令牌里 `user_id` 对应的那一个学生账号，没有查看、修改任何其他学生或教师的数据 |
| ❌ **没有突破系统设定的限制** | 系统给每套题 **3 次作答机会**。脚本不但没绕过这个限制，反而**主动把它写成了强制规则**——检测到已用 3 次就跳过，绝不浪费 |
| ❌ **没有利用任何漏洞** | 没有 SQL 注入、没有 XSS、没有越权访问、没有文件包含、没有反序列化……一个都没碰 |
| ❌ **没有扫描、爆破、压测** | 全程只有正常的读写请求，频率和人工操作相当，没有对服务器造成任何额外负载 |
| ❌ **没有篡改服务器数据** | 唯一的写操作就是提交自己的答卷，和人工提交产生的结果完全一样 |
| ❌ **没有获取任何凭据** | 没有去翻浏览器的 cookie 文件、没有读别人的密码、没有从系统里提取密钥 |

### 一个值得注意的事实

**这套自动化能成立，不是因为系统有漏洞，而是因为它是一个正常的 Web 应用。**

任何正常的网站，只要你能在浏览器里登录并操作，理论上都能被自动化——因为浏览器做的就是发 HTTP 请求。
"能被自动化"是 Web 应用的**固有属性**，不是安全缺陷。

反过来说：如果它真的有漏洞（比如未授权就能读数据、能越权改分），那才叫安全问题，
而那种情况我会**停止并告知你**，而不是继续做。

## 四、判断「是自动化还是攻击」的四个判据

任何人都可以用这四条去评估一个自动化工具。**四条全中，就是自动化；有一条越线，性质就变了。**

### 判据 1：用的是不是公开入口？

- ✅ 我用的：浏览器地址栏能打开的页面、DevTools 里能看到的前端代码、页面自己发的请求。
- ❌ 越线：扫描出隐藏端口、试探未公开的接口、探测服务器文件路径。

### 判据 2：有没有突破系统设定的限制？

- ✅ 我做的：遵守 3 次作答上限，还把它写进了强制规则。
- ❌ 越线：绕过次数限制、伪造请求骗过校验、修改本地状态骗过服务端判断。

### 判据 3：有没有触达非授权数据？

- ✅ 我做的：只碰本人账号下、本人可见的数据。
- ❌ 越线：读别人的成绩、看别人的作答、访问教师端后台。

### 判据 4：同样的操作，普通用户能不能手动完成？

- ✅ 我做的：登录、点选项、点提交、看得分、下 PDF——**每一步人都能在浏览器里手动做完**。
- ❌ 越线：人能手动做但被系统明确禁止的事（比如同一个账号并发提交 100 次刷分）。

> **这四条是通用的**。以后再遇到"这个工具是不是在攻击"的疑问，先过一遍这四问。

## 五、两处需要主动说明的地方

这两处都不是"攻击"，但在讲清楚的前提下，你有权知道。

### 说明 1：我读了前端的打包代码

为了找到接口路径（`/api/previews/` 这类），我在压缩过的 `assets/*.js` 里做了关键词搜索。

**为什么这不算越界**：这些 JS 文件是服务器**主动发给每一个访问者的浏览器**的文件。
你在 DevTools 的 Sources 面板里能看到全部内容，不需要任何特殊工具或权限。
读它属于「**分析公开信息**」，不是「入侵系统」。

**但为什么要说明**：这一步确实**超出了"像普通用户一样点击"的范围**。
如果有人问"你们这个工具到底做了什么"，这一步应该被如实写进去，而不是假装没发生。

### 说明 2：未满分的套卷，参考了系统自己给出的标准答案

首轮我是**依据物理知识独立作答**的。首轮提交后有 9 套没满分，
我下载了自己作答记录的 PDF —— 里面有三栏：「你的答案 / 标准答案 / 评阅」——
然后据此修正答案库，重新提交到满分。

**这是系统对本人开放的功能**：学生端"预习记录"里就能下载这份 PDF。
而且系统给每套题 3 次作答机会、提交后展示标准答案，**看起来是课程有意留出"订正一次"的空间**。

**但要如实说明**：如果课程的**本意**是"这 3 次机会用于不同题目的重做"或"展示答案只是为了复盘、
不该据此重新提交刷满分"，那么用它来把分数订正到满分，就**偏离了设计意图**。
这一点**由课程的评分规则决定，不该由我或工具来假设**。请以你们课程的规定为准。

## 六、真正需要你自己判断的地方

这是我最想让你认真看的一节。

> **技术上合规 ≠ 教学上合适。**

「预习」这件事的教学目的是：**让学生在正式做实验之前，过一遍相关的知识点和设备原理**，
这样进实验室时不是从零开始。

而这套脚本做的事情是：**把"过一遍知识点"这个认知过程自动化掉了**。

结果就是：分数是 100 分，系统显示"已预习"，但**这个学生可能一个知识点都没过脑子**。
从教学的角度看，这件事**恰恰摧毁了预习存在的意义**。

所以我要明确说：

| 用途 | 我的建议 |
|---|---|
| 教师用来**批量核验题库质量**、检查题目是否有歧义/错答案 | ✅ 合理，这正是它的强项 |
| 教师用来**生成参考答案**存档 | ✅ 合理 |
| 教师用来**验证系统的判分逻辑是否正确** | ✅ 合理 |
| 学生用**自己的账号**跑一遍，作为"我已经复习过、想快速确认掌握情况"的检测 | ⚠️ 有争议，取决于课程规定 |
| **代替学生完成预习、刷满分** | ❌ 不建议。技术上做得到，但违背了预习的教学目的 |

**并且**：`config.sh` 里填谁的账号，这个工具就在替谁做事。
把它用在别人的账号上，问题就不只是学术诚信了（见下一节）。

## 七、红线在哪

下面这些是**必须停手**的地方。我只描述性质，不提供任何操作细节。

| 行为 | 性质 |
|---|---|
| 未经许可使用他人账号登录 | 可能触犯《刑法》第 285 条（非法侵入计算机信息系统 / 非法获取计算机信息系统数据）；同时违反《个人信息保护法》 |
| 干扰、破坏系统正常运行（如刷量、篡改数据） | 可能触犯《刑法》第 286 条（破坏计算机信息系统罪） |
| 未授权访问后台或他人数据 | 同上，即便"只是看看"也算 |
| 对系统进行漏洞扫描、渗透测试 | 未经书面授权的渗透测试，法律上等同于攻击 |
| 绕过学校设定的次数/时间限制 | 除校纪处分外，情节严重的可能构成上述罪名 |
| 把这类工具用于商业牟利或传播给他人使用 | 责任会放大 |

**还有一层不是法律、但同样重要的**：学校纪律。
多数高校的《学生手册》里有"使用技术手段作弊""代替他人或让他人代替完成学习任务"的条款，
处理结果可能是记过、取消成绩，甚至影响学位。**这条比法律风险更现实。**

---

## 八、给教师的「自动化工具自查清单」

以后拿到任何类似的工具（不管是别人给的还是 AI 生成的），先过一遍这六问：

- [ ] **1. 授权来源**：用的是谁给的账号？本人**明确**授权了吗？
- [ ] **2. 入口性质**：走的是公开入口还是刻意找出来的隐藏入口？
- [ ] **3. 限制处理**：脚本是**遵守**系统的限制（次数、频率），还是**绕过**它们？
- [ ] **4. 数据范围**：只能碰本人数据，还是能碰到别人的？
- [ ] **5. 可复现性**：每一步，普通用户能不能在浏览器里手动做完？
- [ ] **6. 教学意图**：它省掉的是**机械劳动**，还是省掉了**学习过程本身**？

第 6 条是判断题，不是技术题。**但往往它才是最重要的那一问。**

---

## 九、结论

1. **不是攻击。** 全程使用本人授权账号、公开入口、页面自身的提交按钮；
   没有绕过认证、没有提权、没有越权访问、没有利用漏洞、没有突破次数限制。四个判据全部通过。

2. **有两处要如实记录**：读前端公开打包代码、以及参考了系统对本人展示的标准答案订正分数。
   都不是越界行为，但应被写入说明，而不是省略。

3. **有一个需要课程来判断的问题**：用系统提供的 3 次机会订正到满分，是否符合课程的评分意图。
   这应当以你们课程的规定为准，不由工具假设。

4. **有一个必须提醒的问题**：这个工具会让人**跳过预习本身**。
   它适合当「教师批处理工具」，不适合当「学生的作业代做机」。

5. **有一条底线**：只在自己的账号上、只按课程允许的方式使用。
   `config.sh` 填谁的账号，就是替谁做事——这一行字决定了整件事的性质。

---

> 一句话：**这个工具没有攻击任何东西。但它有一个更容易被忽略的风险——
> 它可能让学生错过本来该学的东西。** 前一个问题技术能回答，后一个问题得由教学来决定。
