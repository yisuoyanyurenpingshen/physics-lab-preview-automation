## 二、逐项展开

### ① 计算机网络

| 知识点 | 具体用到的 |
|---|---|
| HTTP 方法 | GET 读、POST 创建、PATCH 局部更新 |
| 请求头 | `Authorization: Bearer <token>`、`Content-Type: application/json` |
| 状态码 | **200** 成功、**401** 未认证（该续期了）、**403** 已认证但无权限、**409** 冲突（空仓库那个坑）、**422** 参数/已存在 |
| 分页 | `{count, next, previous, results}` 四件套；用 `?page_size=200` 一次拉全 |
| 序列化格式 | JSON 的嵌套结构：对象、数组、JSON 里的键是字符串 |

> **关键区分**：401 和 403 不是一回事。
> 401 = "你是谁？"（没登录 / 令牌过期）→ 应该去续期；
> 403 = "知道你是谁，但你不能看"（权限不够）→ **此时应该停手**，而不是想办法绕过。
> 这个区分在后面合规那一节还会用到。

### ② Web 前端原理

| 知识点 | 具体用到的 |
|---|---|
| DOM | `querySelectorAll` / `innerText` / `className` / `click()` |
| 选择器 | 类选择器 `.el-radio`、属性选择器 `input[placeholder="用户名"]` |
| SPA（单页应用） | 页面不刷新、路由由前端控制、内容靠 JS 渲染 —— 所以"查看源代码"看不到东西 |
| 组件库 | Element Plus 的 `el-` 类名约定、`is-checked` 表示选中态 |
| 受控组件 | 组件状态由框架管理，点一下要等它更新（对应难点 3） |

### ③ 认证与授权

| 知识点 | 具体用到的 |
|---|---|
| JWT 结构 | 三段式 `header.payload.signature`，中间段是 base64 的 JSON，能看到 `exp`（过期时间）、`user_id`、`role` |
| Access / Refresh 双令牌 | access 短命（30 分钟）、refresh 长命（7 天）；用 refresh 换新 access |
| 令牌续期的自动化 | 检测到 401 → 自动换令牌 → 重试原请求（且只重试一次，避免死循环） |
| 会话存哪 | **cookie / localStorage / sessionStorage 的区别**——这个站存在 sessionStorage，所以读 cookie 拿不到 |
| 角色 | 载荷里的 `role: "student"` 决定了哪些接口能用 |

> **一个很实用的知识点**：这三种存储的区别。
> - **cookie**：会自动随请求发给服务器，能设 HttpOnly 防 JS 读取；
> - **localStorage**：永久保存，关浏览器也在，同源共享；
> - **sessionStorage**：只活在当前标签页，关掉就没。
>
> 这个站选了 sessionStorage，所以"关掉标签页就要重新登录"，也所以自动化脚本要在页面里注入它。

### ④ 浏览器原理与调试

| 知识点 | 具体用到的 |
|---|---|
| DevTools | Network（看请求）、Sources（找打包产物）、Application（看存储）、Console（试代码） |
| CDP（Chrome DevTools Protocol） | 浏览器自动化工具底层就是它，用 WebSocket 发指令控制浏览器 |
| 打包产物的阅读 | 压缩过的 JS 里仍然能 grep 出接口路径、字段名 |
| 无头 vs 有头 | 无头更快，有头能看着它跑、便于排错 |

### ⑤ 编程与工程能力

| 知识点 | 具体用到的 |
|---|---|
| 异步编程 | `async/await`、`Promise`、`setTimeout` —— 处理"等页面更新完" |
| 正则表达式 | 从页面文本里抠"已作答 20 / 20""本次得分 100 分" |
| 数据建模 | 答案库怎么设计才能表达"单选 / 多选 / 判断 / 限定作用域的多选" |
| 幂等性 | 脚本反复跑不会重复提交（三道闸的设计） |
| 配置外置 | 账号密码、地址、任务列表全部放 `config.sh`，代码里不写死 |
| 可移植性 | 不硬编码路径（`__dirname` / `cygpath`）、零第三方依赖 |
| 分层设计 | API 层 / 浏览器层 / 编排层各管一件事 |
| 错误处理 | 401 自动重试、某套失败不影响后续、取不到分数返回 `none` 而不是崩溃 |

### ⑥ 数据编码

| 知识点 | 具体用到的 |
|---|---|
| Unicode 码点 | `codePointAt()`；理解 U+1D449 和 U+0056 是两个不同字符 |
| 辅助平面 / 代理对 | U+1D400 以上超出 BMP，JS 里长度是 2，处理时必须用 `u` 标志的正则 |
| 字符区间映射 | 数学字母是**整齐排列**的区间，所以能用"起点 + 偏移量"批量映射 |
| Base64 | GitHub 接口要求文件内容用 base64 传输；JWT 的载荷也是 base64 |
| UTF-8 vs UTF-16 | 文件读写、终端输出、`git ls-files` 的中文转义都跟编码有关 |

> 这一段是整套东西里**最"底层"、也最容易被人忽略**的部分。
> 很多人写脚本卡住不是因为逻辑不会，而是因为不知道"𝑉"和"V"根本不是同一个字符。

### ⑦ 逆向分析方法（这项要特别说明）

我做的不是"黑客式的逆向"，而是**读公开信息**：

- **接口怎么找**：打开 DevTools 的 Network，手动操作一遍，看浏览器发了什么请求。
  这就是最基础、最正当的方法——不需要任何特殊工具。
- **前端代码怎么读**：`assets/*.js` 是服务器**主动发给浏览器**的文件，任何人都能在
  DevTools 的 Sources 里看到。在压缩代码里搜关键词（`submit`、`api`、`previews`）是常规做法。
- **数据结构怎么摸**：直接调接口看返回的 JSON。

**没有任何一步涉及**：猜密码、扫描端口、利用漏洞、绕过权限、伪造令牌。

这一节放在这里，是因为很多同学分不清「**会用工具**」和「**越界**」的区别。
读公开的客户端代码是前者，**动服务器或别人的数据**才是后者。这个界限后面第三份文档会详细讲。

### ⑧ 物理学科知识（这份答案不是猜的）

12 套题分别对应大学物理实验的内容，作答依据的是这些实验本身的原理：

| 实验 | 涉及的核心概念 |
|---|---|
| 弗兰克-赫兹实验 | 原子能级分立、第一激发电位、弹性/非弹性碰撞 |
| 表面张力系数测定 | 表面张力、拉脱法、力敏传感器 |
| 密立根油滴实验 | 电荷量子化、电场力与重力平衡、斯托克斯粘滞阻力 |
| 光栅光谱仪 | 光栅方程、色散率与分辨率、光谱类型 |
| 超声探伤 | 纵波/横波/表面波、压电效应、探头指向性 |
| 卡门涡街（Comsol） | 雷诺数、纳维-斯托克斯方程、有限元与数值模拟 |
| 干涉法测热膨胀系数 | 迈克尔逊干涉仪、等倾干涉、光程差 |
| 阿贝成像与空间滤波 | 傅里叶光学、频谱面、低通/高通滤波 |
| 霍尔效应 | 霍尔系数、载流子类型判断、副效应消除 |
| 光拍法测光速 | 声光效应、多普勒频移、拍频 |
| 金属逸出功 | 热电子发射、理查逊直线法、肖特基效应 |
| 双光栅测微振动 | 多普勒频移、拍频、谐振曲线 |

> **想强调的一点**：工具能帮你省下"点鼠标"的时间，但**答案本身是物理知识**。
> 如果不知道「理查逊直线法是用来做什么的」，改一百遍匹配逻辑也没用。
> 这也是我建议把这类工具定位成"核验与批处理"而不是"代替学习"的原因。

## 三、如果你要自己学一遍（建议路径）

| 阶段 | 学什么 | 能做什么 |
|---|---|---|
| **入门** | HTML / CSS / JavaScript 基础，DOM 操作 | 能用 JS 改一个网页的内容 |
| **第 1 步** | HTTP 基础 + DevTools 的 Network 面板 | 能看懂一个网站和服务器之间在聊什么 |
| **第 2 步** | JSON、RESTful API、状态码 | 能用 Node / Python 调一个开放 API 取数据 |
| **第 3 步** | 正则表达式、字符串处理 | 能从网页/日志里提取想要的信息 |
| **第 4 步** | 异步编程（Promise / async-await） | 能写"等一等再继续"的代码 |
| **第 5 步** | 浏览器自动化（CDP / Playwright 等） | 能写脚本自动操作网页 |
| **第 6 步** | Unicode / 编码常识 | 能处理"看起来一样却不相等"的字符 |
| **第 7 步** | 工程习惯：幂等、配置外置、分层 | 能把一次性的脚本变成能长期用的工具 |
| **一直** | 合规与伦理 | 知道边界在哪，知道什么时候该停手 |

**推荐的第 0 个练习**：找一个公开的、有开放 API 的网站（比如天气、汇率、GitHub 自己的 API），
用 Node 写几行代码把数据取下来打印出来。这一步跨过去，后面的路就顺了。

## 四、一句话总结

> 这套东西真正的知识内核是：**HTTP 怎么说话、浏览器里发生了什么、字符为什么会对不上、
> 脚本怎么才能反复跑不出事**。
>
> 前三条是「读懂世界」，最后一条是「对自己写的东西负责」。
