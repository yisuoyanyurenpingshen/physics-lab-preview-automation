这套工具**用了什么技术、涉及哪些知识、有没有进行攻击** —— 三份文档讲清楚。

配套的脚本在隔壁文件夹 [**大物实验预习-工具包**](../大物实验预习-工具包/)。

## 四份文档

### [01 · 用到了什么技术](01-用到了什么技术.md)

- 目标系统是什么（Vue 3 + Element Plus + DRF + JWT，怎么判断出来的）
- 我这边用了什么（两层结构：API 层读状态 + 浏览器层做动作 + Bash 层管顺序）
- **7 个关键技术难点**逐个拆解：选项随机化、MathJax 公式的 Unicode 陷阱、
  多选状态合并、跨题重复选项、幂等性、Windows 路径、沙箱里 git 推不出去

> 适合：想知道"这东西是怎么做出来的"。

### [02 · 涉及哪些知识](02-涉及哪些知识.md)

九大知识领域的地图：计算机网络、Web 前端、认证授权、浏览器原理、编程与工程、
数据编码、逆向分析方法、**物理学科知识**、合规伦理。

每项都写了"具体用到了什么"，末尾附一条**从零开始的学习路径**（7 步）。

> 适合：想自己学一遍、或者想给学生讲"这里面有什么学问"。

### [03 · 这是攻击吗](03-这是攻击吗.md) ← **最重要的一份**

- 逐条列出**实际做了什么**（7 项）和**明确没做什么**（8 项）
- 给出判断"自动化 vs 攻击"的**四个通用判据**
- **主动说明两处**该说明的地方（读了前端公开代码、参考了系统展示的标准答案）
- 指出**真正需要课程来判断**的问题（用 3 次机会订正到满分是否符合评分意图）
- 划出**法律与校纪红线**
- 附一份**给教师的自动化工具自查清单**（六问）

> 适合：所有使用者。**建议在把工具交出去之前，和工具一起交给对方。**

### [04 · 给你的课程做一套](04-复刻指南.md)

从零复刻的七步路线图：

```
0. 确认授权 → 1. 手动走一遍摸清流程 → 2. 建数据层 → 3. 做执行层
→ 4. 做编排层（防重复提交）→ 5. 让别人能用 → 6. 验收 → 7. 想清楚用途
```

包含答案库设计的**三条铁律**、常见坑对照表、以及第 6 步的验收清单。

> 适合：想把这套方法迁移到**自己课程**的其他系统上。

## 三句话总结

1. **技术上**：这不是攻击，而是一个普通的 Web 自动化工具。
   判断依据是四个判据——公开入口、不突破限制、不碰他人数据、人工可复现，四条全部通过。

2. **方法上**：真正可迁移的不是这几段代码，而是
   「**先摸清流程 → 存内容不存位置 → 富文本先归一化 → 先查状态再动手**」这四句工程习惯。

3. **判断上**：这个工具最大的风险不是"攻击了什么"，而是
   「**它可能让学生错过本来该学的东西**」。
   前一个问题技术能回答，后一个问题得由教学来决定。
