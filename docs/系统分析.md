# 系统分析

对目标系统（实验预习答题系统）的结构化整理，供维护脚本时参考。

## 1. 技术栈

| 层 | 判断依据 |
|---|---|
| 前端 | Vue 3 + Element Plus + MathJax，Vite 打包（资源形如 `assets/index-<hash>.js`），单页应用 |
| 后端 | Django REST Framework（`/api/...` 分页返回 `{count, next, previous, results}`） |
| 认证 | SimpleJWT。`POST /api/auth/login/` 返回 `{access, refresh}` |
| 路由 | 前端路由 `/login`、`/student/previews`、`/student/answer/{id}`；教师端 `/teacher/...` |

## 2. 认证细节

- 令牌是 JWT，前端保存在 **`sessionStorage`**（不是 cookie、也不是 localStorage）。
  - 因此 `document.cookie` 拿不到登录态；复用会话必须写 `sessionStorage`。
- 有效期：`access` 约 **30 分钟**（`iat`/`exp` 差 1800s），`refresh` 约 **7 天**。
- 续期：`POST /api/auth/refresh/`，body `{"refresh": "<token>"}`，返回新的 `access`。
- 令牌载荷含 `user_id`、`role`（`student`）、`name`。
- 请求头：`Authorization: Bearer <access>`。

**脚本的做法**：`scripts/api.js` 负责 HTTP 层（自动检测 401 → 用 refresh 换新 access → 失败则重新登录）；
`scripts/lib.sh` 的 `nav()` 负责浏览器层（打开登录页 → 把两个令牌写进 `sessionStorage` → `location.href` 跳转 → 免表单登录）。

## 3. 接口清单

| 方法 | 路径 | 说明 |
|---|---|---|
| POST | `/api/auth/login/` | 登录，body `{username, password}` → `{access, refresh}` |
| POST | `/api/auth/refresh/` | 续期，body `{refresh}` → `{access}` |
| GET | `/api/auth/me/` | 当前用户信息 |
| GET | `/api/previews/` | 预习任务列表 |
| GET | `/api/previews/{id}/` | 单个任务详情 |
| GET | `/api/previews/{id}/questions/` | 该套的题目（含选项与随机顺序） |
| GET | `/api/attempts/` | 我的作答记录（分页，`?page_size=200` 可一次拉全） |
| GET | `/api/attempts/{id}/pdf/` | 单次作答的答题记录 PDF（含"你的答案/标准答案/评阅"） |
| — | `/api/previews/{id}/scores/` | **学生角色 403**（教师端权限） |

### 3.1 `/api/previews/` 返回字段

```jsonc
{
  "id": 1,
  "paper_id": 1,
  "paper_name": "弗兰克赫兹-试卷",
  "experiment_name": "弗兰克-赫兹实验",
  "start_at": "2026-09-22T00:00:00+08:00",
  "end_at": "2027-01-22T00:00:00+08:00",
  "status": "ongoing",         // 任务态
  "total_score": 100,
  "done": true                 // ← 是否已完成，脚本以此为准
}
```

### 3.2 `/api/attempts/` 返回字段

```jsonc
{
  "id": 464,
  "preview": 10,               // 对应任务编号
  "paper_name": "光拍法-试卷",
  "experiment_name": "光拍法测量光速",
  "attempt_no": 1,             // 第几次作答（每套上限 3）
  "score": 76,
  "total_score": 100,
  "submitted_at": "2026-09-28T09:12:14.784552+08:00",
  "pdf_status": "done",
  "pdf_path": "pdf/10/464.pdf"
}
```

**要点**：
- "某套最新得分" = 该 `preview` 下 `id` 最大的一条 `score`。
- "已用次数" = 该 `preview` 下的记录条数；`≥ 3` 表示机会用尽，不能再提交。
- 答题记录 PDF 是核对标准答案的最佳来源（PDF 三栏：你的答案 / 标准答案 / 评阅）。

### 3.3 `/api/previews/{id}/questions/` 结构

```jsonc
{
  "paper_name": "...",
  "total_score": 100,
  "questions": [
    {
      "id": 217,
      "type": "single",        // single | multiple | judge
      "score": 5,
      "content": "题干...",
      "options": [ { "id": 901, "text": "A. 选项文本" } ]
    }
  ],
  "option_orders": { "217": [..] },   // ⚠️ 每次请求都可能不同
  "question_order": { "single": [..] }
}
```

**关键结论：`option_orders` / `question_order` 每次请求都会变化** —— 实测连续三次请求同一套，题目顺序与选项顺序均被打乱。
因此脚本一律按**选项文本**匹配作答，绝不使用下标。

## 4. 页面 DOM 约定

| 元素 | 选择器 |
|---|---|
| 题目卡片 | `.question-card` |
| 题干 | `.q-title` |
| 单选/判断 | `.el-radio` + `.el-radio__label` |
| 多选 | `.el-checkbox-group` / `.el-checkbox` + `.el-checkbox__label` |
| 已选中 | 元素带 `is-checked` 类 |
| 提交按钮 | `button`，文本含「提交答卷」 |
| 作答计数 | 页面文本 `已作答 N / M` |
| 成绩 | 提交后页面文本 `本次得分 xx 分` |

## 5. 踩坑记录（按发现顺序）

| # | 现象 | 根因 | 解决 |
|---|---|---|---|
| 1 | 按选项序号作答，同一套两次分数不同 | `option_orders` 随机 | 改为按选项**文本**匹配 |
| 2 | 多选题只记录到最后一个选项 | Element Plus 的 checkbox 状态合并 | **逐个** `input.click()`，间隔 150ms |
| 3 | 公式题匹配不上 | MathJax 把公式渲染成 Unicode 数学字母（`𝑉`、`𝑑`）与斜体希腊字母 | 写 `norm()` 做 Unicode→ASCII 归一化 |
| 4 | 5 选项题的 `E.` 前缀没被剥离 | 前缀正则只写了 `[A-D]` | 扩展到 `[A-Z]` |
| 5 | 两道不同题选项文本相同，互相串题 | 全局文本匹配 | `answers.json` 增加 `multiQ`，按题干关键字限定 |
| 6 | 判断题与普通单选题都是 `.el-radio` | 结构相同 | 判断题按**题干关键字**定位（`judges`），其余走 `singles` |
| 7 | `document.cookie` 读不到登录态 | 令牌存在 `sessionStorage` | 用页面内 `sessionStorage.setItem` 注入 |
